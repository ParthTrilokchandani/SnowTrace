What SnowTrace Checks
  • Running processes with path & signature validation
  • Active network connections and unusual ports
  • Persistence: registry run keys, WMI, LSA packages, boot execute, cron, systemd
  • Scheduled tasks and services with suspicious actions
  • User accounts, new admin additions, SSH keys
  • PowerShell / bash history for malicious patterns
  • SUID/SGID files, capabilities, and world-writable directories
  • Security events: failed logins, account creation, log clearing
  • Prefetch, shadow copies, RDP artifacts, USB device history
  • Windows Defender / AV status and recent detections
  • ld.so.preload, PAM backdoors, shell profile tampering
  • Crypto miner detection, package integrity, process memory maps

How To Run SnowTrace
Windows — Step by Step
1
Download the Script
Go to the Download tab and click Download snowtrace_windows.ps1. Save it somewhere accessible (e.g. Desktop or C:\Temp).
2
Open PowerShell as Administrator
Press Win + X → Windows PowerShell (Admin) or Terminal (Admin). Administrator is required for security events, registry data, and driver info.
3
Navigate to Script Location
cd C:\Temp
4
Execute the Script
powershell -ExecutionPolicy Bypass -File snowtrace_windows.ps1
Takes approximately 1–3 minutes. Progress is printed to the terminal.
5
Locate the Output File
Report is saved in the same folder:
snowtrace_windows_HOSTNAME_20240115_103045.txt
6
Upload for Analysis
Drag the .txt file into the Analyze tab above.
⚠ If you see "running scripts is disabled", use Set-ExecutionPolicy Bypass -Scope Process first, or use the -ExecutionPolicy Bypass flag shown above.
Linux — Step by Step
1
Download the Script
Go to the Download tab and download snowtrace_linux.sh. Transfer it to the target Linux system via SCP, USB, or any available method.
2
Make it Executable
chmod +x snowtrace_linux.sh
3
Run with sudo (Recommended)
sudo bash snowtrace_linux.sh
Running as root enables full access to auth logs, /etc/shadow, all user crontabs, and process paths.
4
Locate the Output File
Output saved in current directory:
snowtrace_linux_hostname_20240115_103045.txt
5
Transfer & Analyze
Copy the report to your analysis machine:
scp user@target:/path/snowtrace_linux_*.txt .
Then upload in the Analyze tab.
💡 Tip: If the target has no internet access, use a USB drive or SCP to move the script and output file. The script has no external dependencies.

Remediation Playbooks
⚠ Always preserve forensic evidence before remediating. Take a memory dump and disk image first where possible. Document every action taken.
🔴
Suspicious Process Running from Temp/AppData
▶
Capture the full process path and command line before killing: Get-WmiObject Win32_Process -Filter "ProcessId=PID" | Select-Object *
Check the process's parent PID to understand the execution chain.
Hash the executable: Get-FileHash -Algorithm SHA256 "path\to\file.exe" and check against VirusTotal.
Kill the process: Stop-Process -Id PID -Force
Delete the malicious binary after preserving a copy for forensics.
Search for additional copies: Get-ChildItem -Recurse -Filter "malware.exe" C:\
Check all persistence locations (registry, scheduled tasks, services) for references to the same path.
🔴
Malicious Persistence (Registry / Scheduled Task / Cron)
▶
Windows Registry: Open regedit, navigate to the flagged run key, delete the malicious entry. Document the full value before deletion.
Scheduled Tasks: Unregister-ScheduledTask -TaskName "BadTask" -Confirm:$false
Malicious Service: sc stop BadService && sc delete BadService — verify PathName is removed from disk too.
WMI Subscription: Get-WMIObject -Namespace root\subscription -Class __EventFilter | Where Name -eq "BadFilter" | Remove-WmiObject
Linux Cron: Edit with crontab -e (or crontab -u user -e) and remove suspicious entries. Also check /etc/cron.d/.
Systemd service: systemctl stop bad.service && systemctl disable bad.service && rm /etc/systemd/system/bad.service && systemctl daemon-reload
After cleanup, reboot and re-run SnowTrace to confirm the persistence is gone.
🔴
Unauthorized SSH Key / User Account
▶
Immediately lock suspicious accounts: usermod -L username (Linux) or Disable-LocalUser -Name "username" (Windows).
Review ~/.ssh/authorized_keys for all users. Remove any keys not recognized by your team.
Check if the attacker added themselves to sudoers: cat /etc/sudoers and ls /etc/sudoers.d/.
Rotate SSH host keys: rm /etc/ssh/ssh_host_*; ssh-keygen -A and restart sshd.
Force all users to change passwords: chage -d 0 username (Linux) or via Active Directory.
Review all sessions active during the breach window using last and who /log.
Delete unauthorized user accounts after preserving their home directory for forensics.
🟠
Malicious Network Connection / C2 Communication
▶
Immediately isolate the machine from the network (unplug cable or disable Wi-Fi) to stop ongoing exfiltration.
Capture a network packet dump first if possible: tcpdump -i any -w capture.pcap
Identify the process owning the suspicious connection and kill it.
Block the remote IP at the firewall: New-NetFirewallRule -Direction Outbound -Action Block -RemoteAddress x.x.x.x (Windows) or iptables -A OUTPUT -d x.x.x.x -j DROP (Linux).
Submit the remote IP and downloaded files to threat intelligence feeds (AbuseIPDB, VirusTotal).
Check DNS cache for C2 domains and block them at your DNS resolver or hosts file.
Review all outbound connections from the past 30 days in firewall logs for the same destination.
🟠
PowerShell / Bash History with Malicious Commands
▶
Preserve the history file as evidence before any cleanup.
Decode encoded PowerShell: [System.Text.Encoding]::Unicode.GetString([System.Convert]::FromBase64String('BASE64HERE'))
Trace any downloaded files — check the download path and delete/quarantine payloads.
Check if certutil or bitsadmin was used to download files — look in temp paths for staged payloads.
Review PowerShell Script Block Logs in Event Viewer: Applications and Services Logs → Microsoft → Windows → PowerShell → Operational
Enable PowerShell logging going forward via Group Policy: Script Block Logging and Module Logging.
🟠
SUID/SGID File in Unexpected Location
▶
Compare against your baseline — is this file expected? Check: dpkg -S /path/to/file or rpm -qf /path/to/file.
Hash the file and compare against the vendor's known-good hash.
Remove the SUID bit: chmod u-s /path/to/file
If the file is not from a legitimate package, quarantine and delete it.
Check if the file was recently modified: stat /path/to/file
Audit who has executed this file using audit logs: ausearch -f /path/to/file
🟡
Brute Force / Failed Login Attempts
▶
Identify the source IP(s) of failed login attempts from auth logs.
Block attacker IPs at the perimeter firewall and via fail2ban if configured.
Check if any failed usernames actually succeeded — look for 4624 (Windows) or "Accepted password" (Linux) events from the same IP.
Change passwords for all targeted accounts immediately.
Enable account lockout policy: lock after 5 failed attempts with a 30-minute lockout.
Restrict SSH to key-based auth only: set PasswordAuthentication no in /etc/ssh/sshd_config.
Consider port knocking or moving SSH to a non-standard port as a defense-in-depth measure.
Enable Multi-Factor Authentication (MFA) on all internet-facing services.
🔵
General Post-Incident Hardening
▶
Patch: Apply all OS and application patches. Most initial access exploits known vulnerabilities.
Passwords: Reset ALL passwords on the compromised system, including service accounts and any accounts that authenticated to this machine.
Secrets: Rotate any API keys, certificates, or credentials that may have been exposed.
Logging: Enable enhanced logging — Windows Event Forwarding, Sysmon (Windows), auditd (Linux), and centralized SIEM collection.
Backups: Verify backup integrity and ensure backups are offline/immutable and not accessible from the compromised host.
EDR: Deploy an Endpoint Detection and Response solution if not already present.
MFA: Enable multi-factor authentication on all administrative interfaces, VPN, email, and cloud services.
Least Privilege: Review and reduce admin accounts. Apply principle of least privilege across all accounts.
Network Segmentation: Isolate critical systems. Implement zero-trust network architecture.
Re-image: For serious compromises, re-image from a known-good baseline. Trust is lost once an attacker has root/SYSTEM.
